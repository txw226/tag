# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`tag` is a Kalman filtering library (linear KF + EKF) plus a C++20 orbit propagator bound with nanobind (`tag.propagation`: Kepler solver and two-body `TwoBodyOrbit` so far, see `docs/adr/0001`). It needs Python >= 3.14 (pinned to 3.14 in `.python-version`) and a C++20 compiler (g++ or clang++), and is managed with **uv**, using the scikit-build-core (CMake) backend and a `src/` layout. Dependencies: numpy, plotly (plots); pytest, ruff, mypy, pre-commit, nanobind (stub generation), clang-format, cmake, ninja (dev). All code is kept ruff-clean (check + format), mypy-clean and clang-format-clean; the pre-commit hook enforces all three, and also blocks staged private keys (`detect-private-key`). Commit messages must reference an issue as `#N` (convention: `#N summary`); a commit-msg hook rejects ones that don't, except git-generated Merge/Revert/fixup! messages, and if a hook modifies files the commit fails so the fixes can be reviewed and re-staged.

```sh
uv sync                                    # create/update .venv from pyproject.toml + uv.lock; compiles the C++ extension
uv run pytest -q                           # run all tests
uv run pytest tests/filtering/test_linear_kf.py::test_scalar_constant_matches_running_mean   # single test
uv run python examples/filtering/projectile_kf.py    # sim + filter + plotly HTML (examples/filtering/out/, gitignored); --no-show, --seed N
uv run python examples/filtering/drag_projectile_ekf.py   # same for the EKF on the drag/radar sim
uv run python examples/filtering/drag_projectile_fusion.py  # EKF fusing GNSS + two cameras, vs each alone
uv run python examples/filtering/rocket_drag_estimation.py  # EKF estimating a rocket's unknown Cd (state augmentation)
uv run python examples/filtering/drag_lkf_vs_ekf.py      # drag-free LKF (true / inflated Q) vs EKF on the same GNSS; NEES/NIS, Monte Carlo (--runs N)
uv run python examples/filtering/kf_anatomy.py           # tutorial: one predict/update cycle as covariance ellipses (--step K)
uv run python examples/filtering/tuning_sweep.py         # tutorial: sweep Q / R scale; RMSE, ANEES, ANIS, innovation whiteness (--runs N)
uv run python examples/filtering/pitfalls.py             # tutorial: bad P0, dropout, outliers, sensor bias vs the metrics
uv run python examples/propagation/two_body_day.py       # TwoBodyOrbit: LEO, Molniya, GEO over a day; conservation errors, ns/call and batched ns/point
uv add <pkg>   /   uv add --dev <pkg>      # add a dependency (keeps uv.lock in sync; don't hand-edit)
uv run ruff check --fix && uv run ruff format   # lint + format (config in pyproject.toml, line length 120)
git ls-files -z '*.cpp' '*.hpp' | xargs -0 uv run clang-format -i   # format C++ (.clang-format: LLVM style, column limit 120)
cpp/bench/run.sh                           # build (Release, native, into build/bench) and run the nanobench C++ microbenchmarks
uv run mypy                                # type-check src, tests, examples (config in pyproject.toml)
uv run pre-commit install                  # once per clone: installs the pre-commit + commit-msg hooks (see .pre-commit-config.yaml)
uv run pre-commit run --all-files          # run the hooks over the whole repo
```

The user's shell setup (`~/tag.zshrc`) activates `.venv` automatically and defines `$TagRoot` and the `cdtag` alias.

## Architecture

### Build

- `uv sync`/`uv run` rebuild the extension only when a `[tool.uv] cache-keys` file changes (`pyproject.toml`, `CMakeLists.txt`, anything under `cpp/`), or `SKBUILD_CMAKE_DEFINE` changes. A C++ edit therefore needs no manual reinstall; just `uv run`. Python files are served live from `src/` (scikit-build-core editable redirect). The build is incremental in `build/{wheel_tag}/` (gitignored), and a stale or broken build is fixed by deleting `build/`. A new C++ file must be added to `CMakeLists.txt`, and a file outside `cpp/` must also be added to the cache keys.
- Flags: Release (`-O3`), `-fno-math-errno`, and `-march=native` unless `TAG_NATIVE=OFF` (CI sets `SKBUILD_CMAKE_DEFINE=TAG_NATIVE=OFF` for portable binaries, and compiles via ccache). Never use `-ffast-math`: it breaks NaN checks and Kepler convergence.
- `cpp/include/tag/...` + `cpp/src/...` form the core static library `tag_core`, which uses plain C++ types only. `cpp/bindings/propagation.cpp` is the only file that includes nanobind. It builds the private module `tag.propagation._propagation` and validates inputs there (the core states its preconditions and doesn't check them). `cpp/bench/` holds the nanobench harness (CMake option `TAG_BUILD_BENCHMARKS`, nanobench fetched by FetchContent); add a benchmark as a function called from `main.cpp`.
- `src/tag/propagation/_propagation.pyi` is the extension's type stub, which mypy relies on. It is nanobind stubgen output (with `-P`, so underscore-prefixed internal bindings such as test oracles are typed too) after `ruff check --fix` and `ruff format`, and `tests/propagation/test_stub.py` fails when it's stale (the failure prints the regenerate command). Regenerate it after changing any binding. The build uses the nanobind version locked for the dev group (`extra-build-dependencies` with `match-runtime`), so upgrade nanobind only with `uv lock --upgrade-package nanobind`, and regenerate the stub if the test then fails.

### Packages

One package `tag` (ADR 0001): `tag.filtering` holds the filters, sensors and sims, and `tag.propagation` the orbit propagator; filtering may import propagation, never the reverse. No namespace package. Tests and examples follow the same split: `tests/filtering/`, `tests/propagation/`, `examples/filtering/`, `examples/propagation/`, and the root `tests/`/`examples/` for code using both halves (pytest runs in `importlib` mode, so same-named test files in different folders don't clash). `tag:main` is the `tag` console script.

- `tag.propagation`: re-exports the compiled extension. `eccentric_anomaly(M, e)` solves Kepler's equation (`cpp/src/propagation/kepler.cpp`): reduce M to [−π, π] (Cody–Waite split of 2π), apply Markley's starter, then take 2 fixed Halley steps, using one `sincos` with angle-addition updates. E is returned in M's revolution. `tests/propagation/test_kepler.py` checks it against Vallado Example 2-1 and checks the residual below 1e-15 over sweeps of M and e (e up to 1 − 1e-12). One Halley step fails that sweep.
  - `TwoBodyOrbit(rv, mu=EARTH_MU)` (`cpp/src/propagation/two_body.cpp`): built from an osculating Cartesian state at the epoch (km, km/s, s by default). Construction precomputes n, e, m0 and A = aP, B = bQ, so `propagate(dt)` is one `solve_kepler_reduced` (which also returns sin/cos E) plus r = A(cos E − e) + B sin E, v = n(B cos E − A sin E)/(1 − e cos E): no true anomaly, no atan2. Near e = 0 the perifocal axes are noisy, but every term along them is scaled by e, so near-circular, equatorial and GEO states stay accurate. M = fma(n, dt, m0) is reduced with `reduce_angle`. The bindings validate inputs with `require_elliptic`: `HyperbolicOrbitError` (a `ValueError`, naming e) for e ≥ 1 including parabolic and rectilinear orbits, and `ValueError` for a non-finite state, r = 0 or mu ≤ 0. Bindings that take or return arrays use explicit `nb::sig` signatures (`numpy.typing.ArrayLike` in, `NDArray[numpy.float64]` out), because stubgen's default shape annotation trips ruff and `std::array` stubs as `Sequence[float]`. Batched: `orbit.propagate_many(dts, out=None)` → (N, 6) and module-level `propagate_many(rvs, dts, mu, out=None)` → (M, N, 6), every orbit to every time (core: span overload of `TwoBodyOrbit::propagate` and `propagate_grid`, no allocation in the loop). The bindings convert real numeric array-likes with numpy (nanobind's ndarray caster rejects lists; bool, complex, str and object dtypes are a `TypeError`), copy `dts` so the GIL-free loop can't read memory `out` aliases or another thread changes, never convert `out` (wrong dtype/layout or read-only is a `TypeError`, wrong shape a `ValueError`), validate every row and time before writing anything (errors name the index), then release the GIL; results equal the scalar path bit for bit (`tests/propagation/test_two_body_batch.py`). Measured 2026-11 (`cpp/bench/run.sh` `bench_two_body_batched`, `two_body_day.py`, -march=native): about 75 ns per point in C++ for scalar and batched alike (Kepler-bound); from Python, about 315 ns per scalar `propagate` call (about 240 ns of binding overhead) against about 73 ns per point batched. State transition matrix, opt-in through separate methods so `propagate` is untouched: `propagate_with_stm(dt)` → `(rv, stm)` and `propagate_many_with_stm(dts, out=None, stm_out=None)` → `((N, 6), (N, 6, 6))` (per orbit only, no grid form). Closed form (Battin style): Lagrange f, g, ḟ, ġ differentiated through the epoch scalars r0, σ = r0·v0, α = 1/a and θ = E − E0, with θ's partials from Kepler's equation in difference form (the only secular term is 3/2·n·dt/α), assembled as kI plus outer products of r0 and v0. It reuses the Kepler solution and needs only sin/cos θ (stored sin/cos E0), so there's no revolution count; it costs about 64 ns on top of `propagate`'s 75 ns (`bench_two_body_stm`). Its test oracle is `central_difference_stm` (`cpp/include/tag/propagation/central_difference.hpp`, taking any propagate callable as a `std::function` (no templates in the core), meant for the J2 state transition matrix too), bound only as the private `_two_body_central_difference_stm`; the step is cbrt(eps)·((1 − e)/(1 + e))^1.5/(1 + n|dt|), because truncation error grows with the phase swept and near a high-e perigee (exponent tuned by sweep). It is good to ~1e-10 of the largest entry at low e, ~1e-7 at e = 0.9, only ~1e-5 at e = 0.99 (central differences are ill-conditioned there), so don't test above e ≈ 0.9 against it. `tests/propagation/test_two_body_stm.py` checks the matrix against the oracle (1e-7 of the largest entry, set by Molniya and e = 0.9 ending at perigee; typically 1e-10), symplecticity and forward-then-back composition (both 1e-14 relative to |Φ|², out to 300 periods). `tests/propagation/test_two_body.py` checks Vallado Example 2-4, conservation, round trips, closed-form circular orbits over a year, and an RK4 reference for near-singular orbits. Round-trip tolerances scale with n·|dt|, because rebuilding an orbit from a rounded state perturbs n.
  - Element converters (`cpp/src/propagation/elements.cpp`): `cartesian_to_keplerian`/`keplerian_to_cartesian` (`[a, e, i, raan, argp, anomaly]`, `anomaly="mean"|"true"|"eccentric"`, type alias `AnomalyKind`) and `cartesian_to_equinoctial`/`equinoctial_to_cartesian` (direct set `[a, h, k, p, q, lambda]`, computed directly through the equinoctial frame and Kepler's equation in longitude form, so e = 0 and i = 0 are exact). Index with the exported `KEP_*`/`EQ_*` constants. Keplerian output follows fixed conventions when circular or equatorial (e or sin i below 1e-11, documented in the docstring); equinoctial is singular only at i = 180°. Non-elliptic input raises `HyperbolicOrbitError`. They use the same explicit `nb::sig` signatures as `TwoBodyOrbit`. Tests: `tests/propagation/test_elements.py` (Vallado Examples 2-5 and 2-6, round trips across regimes).
  - Mean elements (`cpp/src/propagation/mean_elements.cpp`, ADR 0002): `osculating_to_mean(rv, mu, re=EARTH_RE, j2=EARTH_J2)` → mean equinoctial elements and `mean_to_osculating(elements, mu, re, j2)` → osculating Cartesian state, first-order J2 Brouwer–Lyddane (short-period plus Brouwer's long-period terms, Lyddane's form via the Schaub & Junkins Appendix F mapping, so e = 0 and i = 0 are regular). `EARTH_RE` = 6378.137 km (WGS-84), `EARTH_J2` = 1.08262668e-3. The core maps equinoctial to equinoctial (`mean_to_osculating_elements`, no mu); osculating → mean is a fixed-point iteration of that map (cap 30, tolerance 1e-12, usually 4–5 iterations), and the round trip is sub-millimetre. The long-period terms divide by 1 − 5cos²i, so the theory is singular at the critical inclination (63.43°/116.57°, where Molniya orbits sit): documented, not fixed. Within roughly 0.01° (e ≈ 0) to 0.5° (Molniya) of it the iteration diverges and the binding raises `ValueError` naming the inclination; a non-finite result is never reported converged. Tests: `tests/propagation/test_mean_elements.py` (round trips across LEO/MEO/GTO/GEO incl. e = 0, i = 0; along one revolution of an in-test RK4 integration of the true J2 acceleration, mean a, e, i are ≥ 25× steadier than osculating, typically ~300×; critical-inclination raise; input validation).
- `src/tag/filtering/kalman/`: filters. `_base.py` holds `FilterResult`, `joseph_update` (the gain is computed with a `solve`, then the Joseph-form covariance update) and `KalmanFilterBase`, which provides `step`/`filter` on top of a subclass's `predict(u)`/`update(z)`. `update(None)`, or a NaN row in `filter`, skips a measurement. `filter` returns prior and posterior states/covariances for every step. Both filters take an optional `accept_posterior(x, P) -> bool`: `update` computes the candidate posterior and the base's `_accept` discards it on False (a rejected update, the prior is kept); `update`/`step` return an `UpdateOutcome` (ABSORBED / SKIPPED / REJECTED). `FilterResult` also holds `skipped` and `rejected` as (N, S) bools (S streams, 1 for `filter`) and `unabsorbed_run` (N,), the lock-out counter `consecutive_unabsorbed` after each step: any absorbed measurement resets it, a step with only rejected ones increments it, a step with no measurement leaves it. `_end_step` advances it; it's report-only unless `max_consecutive_unabsorbed` is set, then `LockOutError` past the limit. Gating (#12) plugs in by adding its outcome to `_UNABSORBED`. Tests: `tests/filtering/test_accept_posterior.py`.
  - `LinearKalmanFilter` (`linear.py`): fixed `F, H, Q, R, (B)` matrices.
  - `ExtendedKalmanFilter` (`extended.py`): callables `f(x, u)`, `h(x)`, with optional analytic `F_jac(x, u)`/`H_jac(x)` (central-difference `numerical_jacobian` otherwise) and an optional `residual(z, z_pred)` for angle wrapping. With linear f/h it reproduces `LinearKalmanFilter` exactly (tested). For fusion, `h`/`R` may be omitted. `update(z, sensor)` then uses any object with `h`, `H_jac`, `R` and `residual`, and `filter_sensors([(sensor, zs), ...])` does one predict per step followed by a sequential update for each stream whose row isn't NaN.
- `src/tag/filtering/sims/`: physics simulations that produce truth plus noisy measurements and the matching model matrices. `projectile.py`: 2D projectile, state `[x, y, vx, vy]`, gravity as a known control input `u = [-g]`, random gusts as piecewise-constant acceleration, so the discrete model is exact and the KF's Q matches the truth's noise. `make_filter(run, ...)` initializes a KF from the first measurement; feed it `run.measurements[1:]`.
- `src/tag/filtering/sensors/`: reusable measurement models (`Sensor` base class): `RangeBearingRadar`, `PinholeCamera` (2D world, so a 1D image `u = f·lateral/depth`; angle-only, and two cameras give stereo) and `GnssPosition`. Conventions: position is at state indices 0 and 1, Jacobians are zero-padded to `len(x)`, `R = diag(noise_std²)`, and `measure_series(truth, rng)` returns NaN rows when the step is off-rate (`every`) or the target isn't `visible`. Noise is drawn for every row, so masking doesn't shift the RNG stream.
- `src/tag/filtering/sims/drag_projectile.py`: projectile with quadratic drag `-k|v|v` (default k = 0.008/m). `simulate_trajectory` gives the truth only, using RK4 with substeps. `simulate` adds a `RangeBearingRadar` at `(-100, 0)` (stored as `run.model.radar`; `model.require_radar()` returns it, or raises if the model was built without radar noise levels). The model's `f` is a single RK4 step, and `F_jac` is that step's exact chained Jacobian. Its `Q` reuses the drag-free `Gamma`, which is approximate under drag. `make_filter` returns a radar EKF initialized from the first measurement. `make_fusion_filter(model, x0, P0)` returns an EKF with no default sensor.
- `src/tag/filtering/sims/rocket.py`: sounding rocket from rail exit to apogee. Thrust acts along v̂ (a gravity turn), and a known `Motor` gives constant thrust with linearly falling mass. It uses an exponential atmosphere. The filter state is augmented to `[x, y, vx, vy, Cd]`, with no process noise on Cd (the truth is constant, and the normalized Cd error checks out without a random walk). Thrust and mass reach the filter as control input `run.controls` = [step-mean thrust, mid-step mass], aligned with measurement rows `[1:]`, so pass `us=run.controls`. The truth holds thrust at its exact mean over each substep, which keeps impulse right at burnout (the rocket equation is tested to 1e-10). `make_filter(..., cd_std=0)` freezes Cd at the guess.
- `src/tag/filtering/sims/_integrate.py`: generic `rk4_step(deriv(t, x), x, dt, deriv_jac)` with the exact chained Jacobian, shared by the drag and rocket sims.
- `docs/kalman_tutorial.md`: concept tutorial (how a KF works, not the API), built around the examples; its numbers come from the examples' default seeds, so update them if an example's parameters change. `docs/img/*.svg` are static diagrams referenced by it.
- `examples/filtering/`: runnable demos with plotly figures; `_plotting.py` holds the shared `band`/`rmse`/`nees`/`nis` helpers and exact χ² quantiles (`chi2_ppf`/`chi2_bounds`, incomplete gamma + bisection, no scipy).
- `tests/filtering/test_projectile.py` holds a Monte Carlo **NEES consistency test** (pooled NEES ≈ state dim 4) plus tests showing it rejects a Q mis-scaled by 4×. Its bounds come from a 20-seed sweep; if you change the sim parameters it uses, re-derive them. Gust strength there is deliberately 2 m/s² because at 0.5 m/s² the process noise is too small to detect mis-tuning over a ~4 s flight.
- `tests/filtering/test_drag_projectile.py` holds the same kind of NEES test for the EKF (gusts 2 m/s², 50 m/s launch). Its bounds also come from a 20-seed sweep, so re-derive them if those sim parameters change.
- `tests/filtering/test_fusion.py` holds a NEES test for GNSS + two cameras, with bounds also taken from a 20-seed sweep. Keep the cameras well away from the flight path: a target within a few metres of a camera makes the projection too nonlinear, and NEES spikes above 100. Stereo-only errors are heavy-tailed, so compare RMSE over at least 20 seeds.
- `tests/filtering/test_rocket.py` holds a NEES test over the 5-element augmented state (≈ 5), with bounds from a 20-seed sweep. It's the slowest test file (about 13 s), because each NEES call simulates 50 flights of about 270 steps.
